## vvvv gamma 8.0
released on XX XX 2026  

### vvvv itself - HDE & Runtime

#### New
- vvvv now runs on .NET 10 (was .NET 8). C# projects referencing VL.Core need to target `net10.0`.
- New package manager, open it with `Ctrl+F3` or via "References..." in the main menu
  - Packages get restored automatically when a document is opened: missing packages get downloaded, no more `nuget install` on the command line
  - The package restore looks at all open documents at once and selects packages based on what is referenced by those documents. Package versions closer to the entry point win. No more arbitrary selection of the latest version found in the user folder (`Documents\vvvv\gamma\nugets`)
  - Browse, search, add, remove and update the package references of a document and pick their versions. Packages can be marked as favorites and are listed by category (All, Featured, By Owner, By Category, Built-in). Deprecated packages are no longer listed <!-- #7561 -->
  - .NET framework assemblies are listed in three sections, Core, Windows Forms and WPF, without duplicates <!-- #7549 -->
  - After removing a reference it stays in the list so the change can quickly be reverted
  - The UI shows when a package restore is in progress, and tells you when a change needs a restart of vvvv and offers to do it
  - Opening a help patch of a package uses the version of that package, regardless of the version stored in the patch. Copying nodes out of a help patch, or saving a help patch somewhere else, stores that version <!-- #7481 #7564 -->
  - Saving a document no longer changes the package versions it references
  - The packages shipped with vvvv have a fixed version. A constraints file lets vvvv warn about package versions known not to work with this vvvv version
  - A package can list its sub-packages in a `vl.subs.json` file; vvvv makes sure they're used in the same version as the main package (for example VL.CEF and VL.CEF.Skia/VL.CEF.Stride) <!-- #7530 -->
  - Opening a document that belongs to a package treats that package as editable, so working on a single source package no longer needs the `--editable-packages` argument
  - If the pre-compilation of a package fails, the error is reported and the package gets loaded from source instead of from a broken cached assembly
  - Package sources can be configured like in any other .NET project
    - A `nuget.config` next to a document or in one of its parent folders is used, for private feeds, credentials and package source mapping. <!-- #7573 -->
    - Central package versions: a `Directory.Packages.props` next to a document or in one of its parent folders defines the package versions <!-- #7491 -->
    - New `project.vl.json` file in a folder or one of its parents: `PackageRepositories` lists package folders for the whole project, `ManagePackageVersionsCentrally` turns the `Directory.Packages.props` lookup off
    - The package manager lists the VL packages of all configured feeds, including private and local ones
- [Boygrouping is back](https://vvvv.org/blog/2026/introducing-distributed-rendering-aka-boygrouping/)
  - The title bar shows the status of the boygroup server or client; hovering it shows details like the bind address, connected clients and startup errors
  - Use `BoygroupServerStatus` and `BoygroupClientStatus` to get information about its state inside the patch
- Problems during startup are shown on the splash screen instead of a console window. Known problems (.NET SDK missing, core packages not restored on a first start without internet) stop the startup with an explanation and actions: Retry, Copy details, Report in forum, Open log folder. Logged errors show up on the splash while loading continues, and a "log" button opens a log below the splash where lines can be copied
- New regions `StatusItem [HDE]` to draw into the title bar of vvvv, `StatusOverlay` to show an overlay below a status item on hover, and `OverlayFactory`
- The Add Channel dialog of the Channel Browser autocompletes the type <!-- #7228 -->

#### Changes
- ArtNet, Firmata, MIDI, OSC, TUIO, WebSocket and Audio packages no longer come with the installer. They get downloaded the first time a patch references them
- Export
  - Exported apps are self-contained by default, they bring their own .NET runtime. Uncheck "Self-contained" in the exporter or use `--self-contained false` to get the former framework-dependent app
  - Optional [Satori GC (experimental)](https://github.com/dotnet/runtime/issues/96213) for self-contained apps
  - The generated NuGet.config contains the package sources vvvv itself uses, so `--export-package-sources` is no longer needed
- Referenced C# projects no longer get their package versions rewritten (introduced in 7.1). vvvv logs a warning instead when they don't align
- Compile errors are logged per document, with their count and first messages, instead of a single "There are build errors."; a missing .NET SDK or a missing project file is reported as such
- Restore and build data is written to `data\restore` and `data\build` in the vvvv folder, or to the AppData folder if the vvvv folder isn't writeable. Several running instances of vvvv no longer write into the same folder
- Pins of C# process nodes with the same name in different fragments (for example the "Result" of two methods) get a unique name like "Update Result" instead of being dropped
- The recently used list no longer checks if files exist, which could lag when they're on a network drive
- Uninstall will delete entire folder - no more left overs

#### Fixes
- Fixes crash when referencing an assembly with the wrong format (a reference assembly or one for a different platform)
- vvvv no longer fails to load a patch whose references have broken dependencies; the type load errors get logged instead
- Fixes crash when opening a .vl file without a document patch, for example an empty file
- Fixes crash when closing vvvv during startup
- Fixes operations of imported hidden classes showing up in the node browser <!-- #7541 -->
- Fixes Channel Browser not updating when patches are docked side by side <!-- #7245 -->

### Standard Libraries

#### New
- `PropertyChanged` node: tells whether a property of an object implementing `INotifyPropertyChanged` changed

#### Changes
- VL.Skia is multi-targeted, packages can reference it without requiring a Windows-specific target framework
- Custom regions can have pins on Create, see [VL-Language#74](https://github.com/vvvv/VL-Language/issues/74). A new base class makes writing such regions easier in C#

#### Fixes
- Fixes ObjectEditor crashing when the value changes - [forum](https://forum.vvvv.org/t/imgui-objecteditor-fails-on-changing-type/25244)
- Fixes FSPickler serialization of `Path`

#### Stride
- `SkiaRenderer` no longer creates new EGL and Skia surfaces every frame - [forum](https://forum.vvvv.org/t/vl-stride-skiarenderer-creates-a-new-egl-surface-and-sksurface-every-frame/25271)
- Adds int versions of the `Input` and `Decl` shaders in ShaderFX
- New `StereoSettings` node for stereoscopic rendering in `SceneWindow`. Rendering falls back to mono when stereo isn't available <!-- #7504 #7505 -->

#### Video
- `VideoPlayer` has an optional "Use Linear Texture Format" input, off by default. The linear format introduced in 7.3 broke playback on some GPUs - [forum](https://forum.vvvv.org/t/video-playback-broken-on-lower-end-amd-devices-in-versions-7-2/25251) <!-- #7547 -->
- `ToVideoStream` nodes (Skia and Stride) take the frame rate as numerator and denominator, which VL.IO.NDI passes on <!-- #7554 -->

#### ImGui
- Adds key mappings for the mouse buttons
- Fixes access violation in `IsKeyPressed` with key `None`
- Fixes crash in `Dropdown` when the list contains null

#### Redis
- Information messages of StackExchange.Redis are logged as Debug, connecting and connected stay on Information - [forum](https://forum.vvvv.org/t/making-vl-io-redis-more-quiet-in-logs/25279) <!-- #7609 -->
